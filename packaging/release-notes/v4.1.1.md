## What's new in 4.1.1

A small release of fixes.

### Local control tells the truth

A button box or a script got `{"ok":true}` for three things that had not happened. It now gets `ok` only
when PushFPS took the request:

- **Save replay**: not `ok` when the replay had nothing to save or could not be written.
- **Screenshot**: not `ok` when another picture was still being saved or the folder could not be used.
- **Scene**: not `ok` for a scene number Streaming mode does not have.

For a replay and a screenshot, `ok` means the request was accepted: the file is written a moment later.
`docs/LOCAL-CONTROL.md` says so.

If the saved token cannot be read (settings copied from another Windows account), PushFPS makes a new one
and says so, and *Settings* no longer shows a token that could not be used.

### Clip markers

When a marker could not be written next to the recording, PushFPS said so but still counted it, and it
turned up in the file with the next marker. A marker that was not saved is now not counted, and the next
one takes its number.

### Check my setup

A reading that was missing could be taken for zero and reported as a problem ("frame generation is falling
behind", "enhancement is worked out at 1080p"). A missing reading is never a finding now.

### Also

- Screenshots are named `pushfps-<time>.png`.
- The capture card row in quick setup shows a mark only for a card that was tested or reported working.
- Texts tidied in the PushFlow 2 switches, the card test and the FSR 4 hint.
