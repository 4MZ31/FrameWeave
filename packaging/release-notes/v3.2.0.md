## What's new in 3.2.0: PushFlow, smoother live play, better recordings and streams

### PushFlow no longer gets stuck at the game's frame rate

PushFlow never refuses to run. When its frames would arrive too late, the frame budget quietly skips them, so a PushFlow that is too slow, or only looked too slow, showed as "stuck at 30 FPS" with no error, on NVIDIA and AMD cards alike. Every cause found in the code is fixed:

- **PushFlow no longer waits on the CPU for every frame.** Each generated frame used to stop the engine thread until the graphics card had finished the network, and the gaps that left on the GPU queue were counted as frame generation cost. The network is now queued on PushFPS's own GPU queue and the next step follows it there.
- **The network has a fixed size.** With a size left open, DirectML could not plan the network ahead and ONNX Runtime ran part of it on the CPU provider. Each PushFlow start now fixes the size, and every part of the network runs on the graphics card.
- **Warm-up at start.** DirectML prepares the network on its first runs. That now happens while PushFlow starts, not on your first frames.
- **A skipped frame pair no longer costs a second one**, and the first measurements after a skip no longer start the next skip (the fix NVIDIA VFG already had).
- **Too slow for your card? PushFlow says so and steps down.** If nearly every pair is skipped for eight seconds, PushFlow moves one tier down (Quality → Balanced → Fast) and tells you why. On Fast it tells you what else would help.
- **Half precision, tested safely.** Half precision can make the network about twice as fast, but it depends on the card and driver. *Professional → Frame generation → PushFlow half precision → Test* now tries it in a separate process, so a driver fault cannot touch PushFPS, and turns it on only if the picture matches and it really is faster.

The time shown for PushFlow in the quick setup is now the network's real time on the graphics card.

### Live play

- **Frame Pacing Repair is on by default** (once, for everyone who never touched the switch). Many console games locked to 30 FPS show their frames 17 and 50 ms apart; that judder is what makes live play look less smooth than a recording. The switch is still in the quick setup.
- **A notice when duplicate removal can't see your game's 30 FPS** (some capture cards add noise to repeated pictures), pointing to the one-click "60→30" fix in the quick setup.

### Recording and going live

- **Two-pass encoding and psycho-visual tuning** (NVIDIA NVENC), for recordings (*Settings → Recording → Advanced*) and for streams (*Go live*). Both are off by default. If your card refuses them, PushFPS keeps your other settings and says so.
- **A stream that is dropped right after it connects** (a wrong or expired stream key, a second stream on the same key) now backs off and stops with a clear message. It used to reconnect every two seconds for as long as you were live.
- **A stream encoder that refused your advanced settings fell back to a variable bitrate.** It now stays on the constant bitrate the platforms ask for.

### Updates

- The in-app update (the banner, or *Settings → About*) downloads the new release, checks its signature and installs it. That path is now run end to end on every build. If an update cannot finish, the installer says why, keeps its window open and starts the version you still have.
- The update banner only appears when the installed version is older than the latest release. (3.1.3 and 3.1.4 offered the update they already had; that was fixed in 3.1.5.) The log now records the installed and latest versions, so a wrong offer can be traced.

### How it was tested

On GitHub's Windows machines, which have no graphics card: the build, the unit tests, PushFlow through DirectML on Windows' software renderer (all three tiers, the queued path against the old waiting path, the half precision test process), the QML tests, the live-stream tests against a local RTMP server, and the install and update test.

**Not tested on real hardware:** PushFlow's speed on NVIDIA, AMD and Intel cards, the NVENC options, and Frame Pacing Repair as a default. The software renderer shows that the new paths are correct, not how fast they are on your card. `PushFlowBench.exe` (next to `PushFPS.exe`) measures that; results are welcome in a GitHub issue.

**Windows Defender note.** Defender may flag new PushFPS downloads as `Trojan:Win32/Tecabans.STV!cl`. This is a false positive from its cloud check on new, unsigned files, and it has been reported to Microsoft. Always check the zip against `SHA256SUMS.txt` on this page.
