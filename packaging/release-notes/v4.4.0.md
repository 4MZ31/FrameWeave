## What's new in 4.4

The crosshair stays where it is.

### Crosshair Hold

Frame generation works out one motion for every place of the picture. A crosshair stands still on the screen
while the world behind it moves, so it was moved along with the world: in every generated frame it was gone
from the middle and showed up twice, to either side. That is the flicker and the ghost copies on a crosshair
the moment you turn the camera, worst in fast pans and while driving.

**Crosshair Hold** deals with the cause. It finds the crosshair, hands frame generation a copy of the picture
without it, and lays the crosshair back, untouched, over every generated frame.

- **Switch it on** in *Quick setup → HUD → Crosshair Hold*. In Pro mode it is in the *Frame Gen* tab.
- **Any shape.** Lines, a dot or a ring: it is found by itself in the middle of the screen. Nothing to draw,
  nothing to set up per game.
- **Only when there is a crosshair.** With none on screen it does nothing, and scenery is left alone.
- **It says what it is doing.** The row reads *Running: crosshair found* while it holds one.
- **With** NVIDIA VFG, DLSS frame generation, FSR, AMD FRC and PushFlow. Not with XeSS or ANR.

A crosshair is picked up once it has stood still over a moving picture for a moment, so right after you aim,
while its lines are still closing in, it is not held yet. A large solid dot with no outline is not picked up.

### Installing and updating

- **An update no longer stops half-way when the virtual camera is in use.** Once the virtual camera had been
  switched on, any program that lists cameras (a browser, Discord, OBS) kept one of PushFPS's files loaded.
  An update or a new install over it then ended with "Copying files failed" and left the folder half old and
  half new. The installer now replaces that file too, and finishes.
- **A copy that fails says which files.** The installer names them and says plainly that the install is not
  complete, where it showed only a number.
