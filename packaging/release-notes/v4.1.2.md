## What's new in 4.1.2

### 60 → 30: a hitch no longer costs a picture

A 30 FPS game that misses a refresh holds one picture a little too long and shows the next one for only a
sixtieth of a second to catch up. Console games do this all the time in heavy scenes. With duplicate
removal on *60 → 30*, PushFPS took every second captured frame whatever it showed: at such a hitch it took
the held picture twice and never saw the short one. Frame generation then got one pair that does not move
and one pair with twice the movement, which shows as a stutter and as artifacts and ghosting round the
character and moving objects.

PushFPS now passes a repeated picture over and takes the next new one, so no picture of the game is lost
and none is used twice. A game that runs below 30 FPS is handled the same way. A picture that really
stands still (a menu, a pause) is still refreshed evenly.

4.0 had this handling; 4.0.1, 4.1.0 and 4.1.1 ran without it.

*Automatic removal* already worked this way and is unchanged.

Built on Veyra 2.2.0: this is how its 60 → 30 mode treats a hitch.
